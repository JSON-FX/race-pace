## Acceptance criteria

1. Super administrators and organization administrators grant an existing runner Pay Later for an event in their organization. Editors cannot grant. Name search is organization-scoped; exact email can locate a new runner account. No category allowlist.
2. Default due date is 28 calendar days before event day. An admin can choose another future date strictly before event day. Store the exclusive next-day midnight boundary in Asia/Manila; display payment through 11:59 p.m. on the due date. Duplicate grants preserve the original deadline.
3. Eligibility holds no inventory. A runner chooses an available category through normal self-registration, including Passport, waivers, add-ons, price and fee rules. The resulting unpaid reservation holds one slot.
4. A category requiring pre-screening requires an approved, live application for the same runner, Passport, event and category. Atomically consume a self-only approved screening hold without double counting. Pending/rejected/foreign applications cannot use Pay Later. Managed or mixed group batches keep their existing flow.
5. Pay Later uses its frozen admin deadline, including when admission closes earlier. It does not bypass closed/cancelled/completed events or suspended organizations. Event admission-deadline edits cannot overwrite the frozen deadline. Existing screening follows current event deadlines, not the prototype's obsolete 72-hour simulator.
6. Reservations show amount, due date, Pay now and unpaid state. No valid QR/check-in before payment. Timely verified payment produces the ordinary paid ticket. At deadline unpaid tickets become invalid and capacity is released through existing provider-safe expiry reconciliation. Late captures never silently revive released tickets or oversell; retain them for reconciliation.
7. Five branded HTML/plain-text emails: grant, reservation, seven-day reminder, one-day reminder, invalidation. Reminder dates already passed are skipped. Send only current unpaid reminders. Jobs are durable, idempotent, retryable and suppress stale paid/expired state. Old payment links show the expired registration.
8. Preserve tenant isolation, current ordinary/group/coming-soon registration, integer-centavo pricing and payment ledgers. Cover concurrency, replay and failure paths in database tests. Preserve approved responsive design and keyboard controls.

## Scope

Admin web and runner site, shared contracts, database and Edge Functions. No mobile redesign, group credit, external lending provider, installment payments, grant extension or refund automation. Existing payment reconciliation handles late provider captures. No production writes or deployment in this implementation step.
