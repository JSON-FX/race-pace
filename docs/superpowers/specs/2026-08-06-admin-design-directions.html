Race Pace Admin — 3 design directions

Same page (Registrations) rendered three ways, so the comparison is apples-to-apples. All three are Next.js App Router + shadcn/ui + Tailwind v4 on your existing trail-green #159A55 tokens — only the density, surface, and layout language differ.

The idea

A calm, Apple-flavoured evolution of what you already have. White sidebar, 14–16px radii, generous row height, soft one-layer shadows. It reads as a premium product rather than an internal tool — and it's the closest visual sibling to your mobile app and the public site.

Lowest riskMatches handoverBrand-consistent

Tables

Roomy 44px rows with avatar + secondary line. Filters live in a toolbar above the card as dropdown buttons; active filters appear as removable chips. Page-size selector, range label, numbered pager.

Trade-off

Least data per screen — ~10 rows visible at 900px. Best when organisers work one event at a time; weaker for scanning 500 registrations.

Filters, sort, page and page-size all live in the URL as searchParams — the page is server-rendered from them, so a filtered view is a shareable link and back/forward restores state.

The idea

Built for the person who lives in this tool on race week. Dark forest sidebar rail that never changes with theme, ~34px rows, monospaced tabular figures, zebra striping, a sticky filter toolbar inside the table card, and ⌘K everywhere. Roughly 2× the rows per screen vs. A.

Most data visibleKeyboard-firstOps/race-day

Tables

The toolbar is pinned to the top of the table card and stays visible while you scroll. Bulk-select reveals an inline action bar. Numbers are mono + tabular so columns never jitter between pages.

Trade-off

Reads more "enterprise tool" than "premium brand". Denser type needs care at 4.5:1 contrast, and it diverges visually from the mobile app and public site.

Same URL-as-state model as A. The extra density comes purely from spacing tokens (--space-* at density 8) — the components are identical shadcn primitives, so A and B can even ship as a user-toggleable "Comfortable / Compact" preference later.

The idea

A bento-grid command center. Large pill controls, 18px radii, an inline detail pane beside the table so clicking a row never navigates away, and segmented status tabs instead of a status dropdown. The most modern-feeling and the most expressive of the three.

Best for the DashboardNo page-jump detailMost distinctive

Tables

Status becomes a segmented tab strip with live counts (the filter you use 90% of the time), leaving the dropdowns for event/category/date. Selecting a row fills the right pane; the pane collapses under 1050px.

Trade-off

Most new UI to build and maintain — the split pane and bento layout are custom compositions, not stock shadcn. The narrower table means fewer columns before horizontal scroll.
